
Python 3.10，PyTorch 2.7.1+cu128 / torchvision 0.22.1+cu128，

SAPIEN 加载器。官方发行包和原库备份都保存在本次日志目录；重装 SAPIEN 后
需要重新应用该环境修复。官方版本说明：<https://www.openimagedenoise.org/>。
RGB 配置不需要 PyTorch3D；点云功能不在此次安装范围内。

pi0.5 策略：

```bash
cd /mnt/liuzihao/project/RoboTwin_feature
source eval_result/setup_20260928/activate_pi05.sh
```

OpenPI 环境位于 `XPolicyLab/policy/Pi_05/openpi/.venv`，Python 3.11，
按 vendored `uv.lock` 安装，包含 `lerobot` 依赖组。安装时临时替换包源 URL，
版本和哈希保持不变，安装后恢复原锁文件。cuSPARSELt 0.7.1 使用通过锁文件 SHA256
校验的本地 wheel 安装，并在同步时排除重复下载。重跑 `uv sync` 可能移除单独以
editable 方式安装的 XPolicyLab，届时需要重新 `uv pip install -e ../../../`。

OpenPI 原锁文件存在一项依赖声明冲突：`rerun-sdk` 要求 NumPy >=2，
而 OpenPI 的 override 固定 NumPy 1.26.4。本次保留模型版本约束；
`pi05_pip_check.log` 记录该冲突，Rerun 可视化不属于本次验收范围。

## 六类采集

`blocks_ranking_color_order`，使用现有 `color_order` 配置。
成功 episode 按 RGB、RBG、GRB、GBR、BRG、BGR 循环，600 条即每类 100 条。
GPU 7，正式配置 `save_freq: 15`，保持原有随机种子、规划和回放验证机制。

```bash
tmux attach -t robotwin-collect
```

流程先用 `color_order_smoke` 采集六条并检查 HDF5 的目标、语言、三路 RGB、
有限动作数值及视频，再启动 600 条正式采集。正式输出：

```text
data/color_order/blocks_ranking_color_order/aloha_agilex/
```

采集脚本先搜索成功 seed 和规划轨迹，再回放写出 HDF5。因此开始时可以已有
`seed.txt` 和规划文件，但还没有正式 HDF5。中断后可用原命令续采：

```bash
CUDA_VISIBLE_DEVICES=7 python scripts/collect_data.py \
  blocks_ranking_color_order color_order --episode-num 600
```
